Most of what customers ask has been asked before.

A support bot that asks a large AI model every time pays for the same answer over and over. This project teaches a small, cheap model to handle the repeats, and checks that it can be trusted before it answers.

Today, every question goes to the big AI.

A bank's support bot reads each message and decides what it is about: a lost card, a failed transfer, a question about fees. A large language model does that reading, and it charges for every message, even the thousandth "where is my card?"

Its answers become lessons.

Every answer the big AI gives is a free example. A small model, cheap enough to run on an ordinary computer, studies those examples: this wording means "card arrival", that wording means "transfer failed".

Then the small model takes the easy ones.

A gate sits in front of it. When the small model is sure, it answers. When it isn't, the question goes to the big AI. About half of all questions now never reach the big AI.

Then something new happens.

The bank launches virtual cards. Customers ask things the small model has never seen, and it answers them with confidence, wrongly, because it only knows older topics that sound similar.

The gate gets cautious, and the model gets lessons.

Wrong answers on a topic make the gate more careful there, so those questions go back to the big AI. The big AI's answers retrain the small model, with extra weight on the new topic so its older look-alikes don't drown it out.

Half the calls. About the same accuracy.

That is the whole idea: copy what the big AI does when it is routine, hand questions back when something is new, and keep learning without anyone watching.

What didn't work.

The project started with a different idea. These are the parts that did not hold up, because the results are only worth trusting if the misses are on the page too.

The original idea didn't beat a simpler one.

I first built a "stress field" (the code calls it cortisol): a worry level that rises in the topics where mistakes happen. Against a plain gate with retraining, it showed no advantage. It is still in the code, labelled experimental.

My first pick failed on fresh data.

The first recommended setting looked fine on the runs I tuned on, then lost 3.4 points on new-product questions on the held-out runs. The cause was imbalance after retraining; weighting the new topic fixed most of it. That fix came after I had seen the held-out result, so the numbers above are not a fully clean test.

A per-topic version helps only close to home.

Spreading worry between related topics beat the plain gate when a whole new set of intents resembled old ones (credit cards after banking). It did not when the new topics were far away (travel). A whole new domain is still hard for every setting.

An AI "sensor" never fired.

I added a check that asks the big AI which known topics an unfamiliar cluster might be confused with. As designed, the trigger never fired. Loosened, it fired a handful of times and changed nothing measurable.
